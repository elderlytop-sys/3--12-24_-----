## 1–2. CHECK и UNIQUE

Таблица `product` создана с полями `name TEXT NOT NULL UNIQUE` и `price REAL CHECK (price >= 0) DEFAULT 0`. `UNIQUE` запрещает повтор имени, `NOT NULL` запрещает отсутствие имени, `CHECK` не допускает отрицательную цену.

В SQLite ограничение `UNIQUE` задаётся при создании таблицы; добавить его обычным `ALTER TABLE` нельзя, поэтому оно включено в `CREATE TABLE`.

## Задача на поиск ошибки

В запросе `SELECT name, CASE WHEN price > 100 THEN 'дорого' FROM product;` отсутствует `END`, закрывающий выражение `CASE`. Корректный вид: `CASE WHEN ... THEN ... ELSE ... END`.

## Задача на предсказание результата

`COALESCE(NULL, NULL, 5)` возвращает первое значение, которое не равно `NULL`, то есть **5**.

| result |
| --- |
| 5 |

## Продвинутый случай. CASE в UPDATE

Запрос `UPDATE product SET price = CASE WHEN price < 0 THEN 0 ELSE price END` включён в `02_tasks.sql`. В таблице `product` отрицательные значения уже запрещены через `CHECK`, поэтому отдельная таблица `price_fix_demo` показывает фактическое исправление ошибочной отрицательной цены на 0.

| id | name | price |
| --- | --- | --- |
| 1 | Ошибка ввода | 0 |
| 2 | Корректная цена | 50 |

## Проверка ограничений

`verify_constraints.py` проверяет `CHECK`, `UNIQUE`, `NOT NULL`, `DEFAULT`, `COALESCE`, `NULLIF` и обновление через `CASE`. Результаты сохранены в `constraint_checks.json`.
