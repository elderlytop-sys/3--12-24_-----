## Краткая теория

- `INNER JOIN` возвращает только строки с совпадением в обеих таблицах.
- `LEFT JOIN` возвращает все строки левой таблицы; при отсутствии совпадения справа выводится `NULL`.
- `RIGHT JOIN` сохраняет все строки правой таблицы.
- `FULL OUTER JOIN` сохраняет все строки обеих таблиц; для несовпавшей стороны выводится `NULL`.
- Условие соединения указывается через `ON`. Если его забыть, получится декартово произведение.
- Псевдонимы (`p`, `c`, `s`) сокращают запись и делают запросы понятнее.

SQLite поддерживает `RIGHT JOIN` и `FULL OUTER JOIN` начиная с версии 3.39.0; используемая версия 3.46.1 поддерживает оба оператора.

## Задача на поиск ошибки

Запрос `SELECT p.name, c.name FROM product p JOIN category c;` не содержит условия `ON`. В результате каждая строка `product` соединяется с каждой строкой `category`: получается декартово произведение. В учебной базе 5 товаров и 3 категории, поэтому будет 15 строк, а не только реальные соответствия.

Число строк в проверочном запросе: **15**.

## Задача на предсказание результата

Для `Хлеб (cat=1)` найдётся категория «Еда». Для `Сыр (cat=NULL)` совпадения не будет, поэтому название категории будет `NULL`. `LEFT JOIN` сохраняет обе строки товара.

| name | category |
| --- | --- |
| Сыр | NULL |
| Хлеб | Еда |

## Продвинутый случай

`RIGHT JOIN` можно переписать через `LEFT JOIN`, поменяв таблицы местами: `FROM category c LEFT JOIN product p ON p.category_id = c.id`. Так сохраняются все категории, даже если у них нет товаров.

| product | category |
| --- | --- |
| Хлеб | Еда |
| Молоко | Еда |
| Чай | Еда |
| Мыло | Быт |
| NULL | Напитки |
